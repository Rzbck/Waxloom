# Waxloom Import V3 — 24 October 2026

Source: branch `feat/import-pixel-v3-20261024`, based on the previously deployed Web/API commit `0156386fa75f9cf2d0e268f32a595baab5c0e8fa`. No automatic merge into `main`.

## User pain points addressed
- Original synthetic art looked like geometric rings/lines, not record sleeves. Replaced with **nine deterministic 32×32 illustrated pixel-art scenes** (night city, mountains, lake, railway, desert, lighthouse, meadow, skyline). Eight restrained palettes; no repetitive WAX label. Pure SVG data URIs render without network. True cover photos always override the synthetic art.
- Search songs/albums/playlists were missing visual thumbnails: video thumbnails now use canonical YouTube `i.ytimg.com` sources; playlist art attempts the real playlist thumbnail, then independently expands the first few items to find a public video thumbnail. Below-fold covers lazy-load via IntersectionObserver, limited to 3 concurrent metadata lookups, with instant pixel placeholder. URL validation remains strict.
- Search results are square artwork **cards** with title/artist below, not a duplicate crowded list. A selected album/playlist opens a distinct hero with larger artwork, channel and song count, a scrollable/compact track list, play/seek and **download whole collection**. Direct **+** on an album or individual song queues through the existing Discovery 2-worker download manager, with explicit first-use media authorization and optional playlist destination.
- Removed duplicate download queue from Import; the existing global Discovery Downloads popup stays. Failed jobs now show the full error under their phase, rather than ellipsis plus cryptic "1 review".
- Previewed Import songs retain their exact canonical YouTube ID and artist/title on the persistent bottom player. That player's direct download button now uses selected video URL, never a fuzzy re-search. Playlist add in the bottom player also uses the exact selected video ID. Media-session preview retries re-resolve the expiring signed HTTPS URL rather than incorrectly treating `yt:...` as a MusicBrainz recording.
- The source `Machinegewehr - Carradine` in the independent-label channel *Les Yeux Orange* was falsely refused by the strict automatic music score: real metadata has M4A audio, 340 seconds, but score 1.5. Selected-source imports now accept real standalone 45–900-second audio-only videos unless unmistakably nonmusic, rather than requiring provider "Music" tags. Discovery auto-selection retains its stricter fuzzy-match behavior.
- Improved relevance ranking for tracks and playlists; require 75% of query tokens and penalize "solved", interviews, reviews and other commentary. Verified real query *Carradine Machinegewehr* returned the two intended songs; unrelated album search candidates no longer fill the list. Artist **channels** are found independently; tap a channel to browse its real public playlists, with strict channel IDs; real Ben Böhmer channel listed 10 playlists.
- Preview metadata extraction now falls back to explicit signed HTTPS audio-only formats if yt-dlp's top-level format is missing or non-playable; failed previews are automatically removed from first visible results after a **two-worker nonblocking validation** of first 6 songs, or after later failed play/hover. No guarantee every third-party link will always remain accessible.

## Deployment rules
Web and API **must** be built and deployed together from the same immutable published commit (new channel APIs and provider rules require both). Preserve old V2 immutable images (`waxloom-web:import-v2-0156386`, `waxloom-api:import-v2-0156386`) and SHA256-verified snapshots of production Compose, Nginx and runtime manifest. Isolated staging HTTP 200, OpenAPI routes, JS/CSS and byte-range regression before guarded rollout; rollback both services on failure. Never modify music library, existing user worktrees, other services, browser tabs or task scheduler.
