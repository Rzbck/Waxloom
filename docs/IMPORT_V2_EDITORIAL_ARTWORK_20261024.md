# Waxloom — Import YouTube V2, editorial art, persistent cover cache (2026-10-24)

## Owner objective and baseline
- A single fast music search box for artist, track, album, playlist or direct YouTube URL, with multiple selectable tracks, preview playback with real seek, optional destination playlist and instant queue. Reuse the proven Discovery download engine rather than implementing a second downloader.
- Existing import required separate Artist + Title, selected only one video, did not provide integrated preview/seek. Existing Discovery has media player + 2 worker queue and verified Navidrome import/download/playlist logic.
- Existing generated album cover artwork was too saturated/abstract and printed **WAX** on every item. True covers were slow; 13/24 live sampled covers were the exact same generic Navidrome 69,228-byte WebP image.
- User accepts a reversible UI experiment, not any API subscription or new services.

## Implemented functionality
- `apps/web/src/ImportsView.tsx`, `imports-v2.css`: one field, direct YouTube album/playlist URL, fast track results and asynchronously discovered collections; tags (Tracks/Albums/Playlists), select one/multiple/all, open collection to select constituent tracks, Play/Pause per track, inline audio seek using the existing player, optional editable artist/title tags, choose library or an existing playlist, explicit media authorization checkbox, persistent page download queue statuses. Responsive 320px+.
- `apps/api/src/waxloom_api/youtube_browse.py`: strict YouTube URL canonicalization prevents SSRF/redirect tricks; bounded `ytsearch` metadata lists without downloading streams; separate playlist-only search so slow album search never holds up songs; bounded playlist expansion (80 tracks max); resolves short-lived HTTPS direct seekable audio URLs **on demand** with a small 80-second cache. No new paid YouTube API, no external account or scraper of ChatGPT.
- `apps/web/src/api.ts`: new typed browse, collections, expand, preview APIs; 5-minute coalesced in-memory browse cache; first preview warms asynchronously after search results paint, pointer-hover warmup supported.
- `apps/web/src/Player.tsx`: imports can pass a verified resolved direct audio URL to the existing Discovery player; exposes currentTime/duration, playback toggle, native seek. Existing audio handoff, preview and shuffle modes remain unchanged.
- `apps/web/src/downloadQueue.tsx`: new selected-source jobs plug straight into the **same two-concurrent Discovery worker pool**, use the precise user-selected canonical YouTube source instead of a second fuzzy search, dedupe queued songs, preserve explicit authorization, existing Navidrome scanning and optional playlist addition; up to 120 tracked items rather than 16.
- `apps/web/src/CoverArtwork.tsx`, `cover-editorial.css`: 8 original restrained record-cover styles (cinematic/nocturnal, analog, minimal, abstract landscape, paper collage). Curated palettes only, no text / WAX branding on artwork. True album images continue to override the synthetic art on decode.
- `apps/api/src/waxloom_api/cover_cache.py`: persistent max 320 MB thumbnail disk cache in the API's **already mounted** `/data/Waxloom/cover-thumbs`; first fetch reuses Navidrome's sized artwork, subsequent requests serve local disk with ETag and cache headers. SHA-matched Navidrome generic logo returns a short-term cached negative response, so it does not waste bandwidth and Waxloom shows the editorial artwork. 7-day thumbnail refresh, bounded in-flight fetches, periodic best-effort pruning. No new Windows services or scheduled tasks.
- `main.py`: adds `/api/imports/youtube/{browse,collections,expand,preview}` and moves `/api/media/cover/{id}` to persistent cache. Legacy `/api/imports/youtube/search`, original Discovery queue/import endpoints and music streams untouched.

## Tests and measured results
- New Python tests `test_youtube_browse_and_cover_cache.py`: canonical URL guard, SSRF rejection, query/collection expansion and cache, real single-file id, approved signed preview destination, audio-only preview, album list nonblocking, local cover caching even with a fresh cache instance, and stock image suppression. **38 backend tests PASS** including old suites; 4 pre-existing FastAPI `on_event` deprecation warnings.

- New isolated Chrome imports suite: one-field search, songs + collection, expansion to 3 songs, source preview playback through common player, native seeking to 3.0sec, pause, bulk selection, 3 queued jobs with maximum **2 active**, 3 playlist additions; widths 320/390/768, zero horizontal overflow. **PASS**. Mock intercepts all imports and makes **zero real download or media modifications**.
- Other browser QA: responsive album/artist/favorite grids, synthetic Home shuffle/continuous MediaSession Next, iOS Home Screen audio and mobile controls all PASS. Pure tests: 5,124 Smart Autoplay assertions, 1,964 metadata assertions, 18 iOS helper assertions. TypeScript/Vite build PASS; npm high audit 0 vulnerabilities.
- Old server already had long browser artwork cache, but a cold image can still depend on Navidrome. Generated artwork is first-paint, persistent API cache accelerates future requests; the first uncached real cover cannot be literally instant. On actual iPhone Safari, signed direct YouTube audio and seek remain a physical device acceptance step.
